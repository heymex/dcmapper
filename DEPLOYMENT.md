# Production Deployment Guide

## Security Requirements

### Image Tag Pinning

**CRITICAL**: Production deployments MUST use immutable image references to prevent supply chain attacks. The `docker-compose.komodo.yml` file requires explicit specification of `DCMAPPER_IMAGE_TAG` with no default value.

### Why Immutable Tags Matter

Mutable tags like `latest`, `v1.0.0`, or `1.0` can be overwritten by an attacker who gains access to the GitHub Container Registry. Using immutable references ensures that:

1. The exact image content is verified and cannot be changed without detection
2. Deployments are reproducible and auditable
3. Rollbacks reference the exact same image that was previously deployed

## Deployment Methods (Ordered by Security)

### 1. Digest Pinning (Most Secure - Recommended)

Pin to both the SHA tag and the image digest:

```bash
# Set in your .env file or Komodo stack configuration
DCMAPPER_IMAGE_TAG=sha-abc1234@sha256:def567890abcdef567890abcdef567890abcdef567890abcdef567890abcdef
```

**Advantages:**
- Cryptographically verifies image content
- Completely immutable - cannot be changed without detection
- Provides strongest supply chain security

**How to find the digest:**
1. Check the GitHub Actions workflow summary after a build
2. Visit https://github.com/heymex/dcmapper/pkgs/container/dcmapper
3. Use `docker pull ghcr.io/heymex/dcmapper:sha-abc1234` then `docker inspect` to get the digest

### 2. SHA-Based Tag (Secure)

Use the immutable SHA tag generated by CI:

```bash
# Set in your .env file or Komodo stack configuration
DCMAPPER_IMAGE_TAG=sha-abc1234
```

**Advantages:**
- Immutable - tied to a specific git commit
- Easy to correlate with source code
- Cannot be overwritten in the registry

**How to find SHA tags:**
1. Check the GitHub Actions workflow summary after a build
2. Visit https://github.com/heymex/dcmapper/pkgs/container/dcmapper
3. SHA tags follow the pattern `sha-<7-char-git-sha>`

### 3. Semantic Version Tag (Not Recommended for Production)

```bash
# NOT RECOMMENDED - mutable tag
DCMAPPER_IMAGE_TAG=v1.0.0
```

**Disadvantages:**
- Mutable - can be overwritten by an attacker
- Does not provide supply chain security
- Should only be used for development/testing

## Deployment Workflow

### Initial Deployment

1. Identify the commit SHA you want to deploy from the GitHub repository
2. Wait for the GitHub Actions workflow to complete for that commit
3. Check the workflow summary for the SHA tag (e.g., `sha-abc1234`)
4. Set the environment variable in your Komodo stack:
   ```bash
   DCMAPPER_IMAGE_TAG=sha-abc1234
   ```
5. Deploy using Komodo or `docker compose up -d`

### Updating to a New Version

1. Identify the new commit SHA to deploy
2. Verify the GitHub Actions workflow completed successfully
3. Update the `DCMAPPER_IMAGE_TAG` in your environment configuration
4. Redeploy: `docker compose pull && docker compose up -d`
5. Verify the deployment: `curl https://your-domain/healthz`

### Rollback Procedure

1. Identify the previous working SHA tag from your deployment history
2. Update `DCMAPPER_IMAGE_TAG` to the previous SHA tag
3. Redeploy: `docker compose pull && docker compose up -d`
4. Verify the rollback: `curl https://your-domain/healthz`

## Environment Configuration

Create a `.env` file in your Komodo stack directory with the following required variables:

```bash
# REQUIRED: Immutable image reference
DCMAPPER_IMAGE_TAG=sha-abc1234

# REQUIRED: Domain configuration
DCMAPPER_DOMAIN=dcmapper.example.com

# REQUIRED: Database password
POSTGRES_PASSWORD=<strong-random-password>

# Optional: Certificate resolver (default: cf)
DCMAPPER_CERT_RESOLVER=cf

# Optional: Admin configuration
DCMAPPER_ADMIN_NAME=admin

# Optional: CORS configuration
ALLOWED_ORIGINS=https://dcmapper.example.com

# Optional: Rate limiting
RATE_LIMIT_WINDOW_SECONDS=60
RATE_LIMIT_MAX_REQUESTS=120

# Optional: Schema management
DCMAPPER_AUTO_CREATE_SCHEMA=false
```

## Verification

After deployment, verify the following:

1. **Health check**: `curl https://your-domain/healthz`
2. **Image digest**: `docker inspect dcmapper-roch-web | jq '.[0].Image'`
3. **Container logs**: `docker logs dcmapper-roch-web`
4. **Database connectivity**: Check that the app can connect to PostgreSQL
5. **API endpoints**: `curl https://your-domain/api/locations`

## Security Best Practices

1. **Never use `latest` tag in production**
2. **Always pin to SHA tags or digests**
3. **Keep deployment history** of which SHA tags were deployed when
4. **Monitor GitHub Actions** for unexpected builds or tag updates
5. **Rotate database passwords** regularly
6. **Review GHCR access permissions** periodically
7. **Enable GitHub branch protection** on the main branch
8. **Require signed commits** for additional security
9. **Audit container registry access logs** regularly

## Troubleshooting

### Error: "DCMAPPER_IMAGE_TAG must be set"

This error occurs when `DCMAPPER_IMAGE_TAG` is not defined. This is intentional to prevent accidental use of mutable tags.

**Solution**: Set `DCMAPPER_IMAGE_TAG` to a valid SHA tag in your `.env` file.

### Error: "manifest unknown" or "not found"

This error occurs when the specified tag does not exist in the registry.

**Solution**: 
1. Verify the tag exists at https://github.com/heymex/dcmapper/pkgs/container/dcmapper
2. Ensure the GitHub Actions workflow completed successfully
3. Check for typos in the tag name

### Container fails to start

**Solution**:
1. Check container logs: `docker logs dcmapper-roch-web`
2. Verify database is healthy: `docker ps` (check health status)
3. Verify environment variables are set correctly
4. Check database connectivity from the container
